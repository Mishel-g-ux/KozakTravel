# Командна конвенція (KozakTravel)

Цей документ описує спільні правила команди. Оскільки сайт створено на конструкторі Wix, а не написано кодом, конвенція стосується організації роботи в репозиторії та оформлення контенту сайту.

## 1. Гілки

- `main`: стабільна версія, зміни потрапляють сюди лише через Pull request.
- Робочі гілки: `<тип>-<розділ>`, лише малі латинські літери та дефіс.
  - Приклади: `page-tours-europe`, `page-news`, `docs-test-cases`, `fix-contact-form`.
- Типи гілок: `page` (розділ сайту), `docs` (документація), `fix` (виправлення), `test` (тести).
- Одна гілка відповідає одній задачі зі Sprint Backlog.

## 2. Коміти

Формат: `тип: короткий опис українською`, до 70 символів, без крапки в кінці.

| Тип | Коли використовувати | Приклад |
|---|---|---|
| `content` | Додано або змінено текст, фото, ціни | `content: додано опис турів по Європі` |
| `docs` | Документація, беклоги, конвенція | `docs: додано тест-кейси` |
| `test` | Результати тестування | `test: результати димових тестів` |
| `fix` | Виправлення помилки | `fix: виправлено посилання в меню` |
| `chore` | Службові зміни (налаштування) | `chore: додано Doxyfile` |

Один коміт містить одну логічну зміну.

## 3. Pull request

- Назва PR збігається з назвою основного коміту.
- В описі: що зроблено і на яку задачу зі Sprint Backlog (`S5`, `S6` тощо) це посилається.
- Перевіряє та зливає PR Scrum Master (Сивицький Артем); автор PR його не зливає.

## 4. Назви файлів

- Латиницею, малими літерами, слова через дефіс: `tours-europe.md`, `main-page.png`.
- Скріншоти: `<розділ>-<опис>.png`, наприклад `tours-europe-list.png`.
- Документи в папці `docs/`, скріншоти в `screenshots/`, дані спринту в `sprint/`.

## 5. Оформлення контенту сайту

- Мова інтерфейсу та текстів: українська.
- Ціни в єдиному форматі: `від 1 200 €` (число з пробілом як роздільником тисяч, символ валюти після числа).
- Назви турів: з великої літери, без крапки в кінці (`Подорож Італією`).
- Заголовок сторінки один (H1), підзаголовки по порядку (H2, H3), без пропуску рівнів.
- Усі зображення мають альтернативний текст (alt).
- Кольори й шрифти беруться з єдиної теми сайту, власні кольори на окремих сторінках не додаються.
- Головне меню та футер однакові на всіх сторінках.

## 6. Issues (відстеження проблем)

- Назва: коротко, що не працює (`Сторінки турів показують шаблонний текст`).
- В описі: де, кроки відтворення, очікуваний і фактичний результат, скріншот.
- Мітки: `bug` (помилка), `content` (потрібен контент), `enhancement` (покращення).
- Виправлений Issue закривається посиланням на PR (`Closes #N`).

## 7. Markdown-документи

- Заголовки через `#`, таблиці Markdown, один порожній рядок між блоками.
- Назви розділів однакові у всіх документах (Product Backlog, Sprint Backlog тощо).
